Phase 0B Model Purpose

현재 구현된 account/auth foundation 모델의 역할과 컬럼 목적을 MVP 요구사항 기준으로 정리한 문서다. 기준 코드는 apps/accounts/models.py와 apps/accounts/enums.py, apps/accounts/migrations/0001_initial.py다.

Phase Phase 0B - account/auth foundation
Scope User, social account, email/token, benefit ledger
MVP 기준 계정 기반과 관리자 인증만 구현
Excluded Seller, marketplace, coupon system, commerce flows

Model Configuration And Enums

이 항목들은 DB 컬럼은 아니지만 custom User와 enum 선택지를 이해하는 데 필요한 모델 설정이다.

accounts.models / accounts.enums
Item Purpose MVP justification
USERNAME_FIELD = "email" Django 인증에서 email을 로그인 식별자로 사용한다. Phase 0B 결정: username이 아니라 email 로그인을 기준으로 한다.
REQUIRED_FIELDS = [] createsuperuser가 email/password 외 추가 필드를 묻지 않게 한다. DB 컬럼이 아니라 Django custom user 설정이다. USERNAME_FIELD가 email이므로 별도 필수 입력 필드는 없다. username은 manager가 자동 생성한다.
SocialProvider 소셜 provider 선택지. 현재 kakao, naver. Phase 0B 초기 소셜 로그인 범위가 Kakao/Naver다.
UserTokenPurpose email_verify, password_set, password_reset token 목적을 표현한다. 같은 token 모델을 Phase 0B 인증 작업에 재사용한다.
BenefitClaimCode 혜택 ledger의 claim 종류. 현재 welcome_signup. MVP에서 중복 지급을 막아야 하는 혜택은 웰컴 혜택이다.

User Manager Behavior

UserManager는 DB 컬럼을 추가하지 않지만 User 생성 경로의 기본 정합성을 담당한다.

accounts.managers
Behavior Purpose MVP justification
normalize_email() email 앞뒤 공백을 제거하고 전체 주소를 소문자로 변환한다. Phase 0B 결정: 가입, 로그인, 연결 lookup은 정규화 email 기준이다.
generate_username() 초기 username을 user_{random8} 형태로 자동 생성한다. username은 로그인 ID가 아니며 가입 시 사용자에게 필수로 받지 않는다.
set_password(password) 비밀번호 원문 대신 Django password hash 또는 unusable password를 저장한다. 이메일 가입과 소셜 가입 모두 하나의 User 생성 경로에서 안전하게 처리한다.
full_clean(exclude=["password"]) 저장 전에 email 형식, 길이, unique, model constraints를 검증한다. password hash 필드는 Django auth 규칙에 맡기기 위해 제외한다. manager로 생성되는 User가 Phase 0B 모델 제약을 DB 저장 전부터 만족하게 한다. 최종 정합성은 여전히 DB constraint가 보장한다.
create_superuser() superuser 생성 시 is_staff와 is_superuser를 강제한다. 관리자 REST baseline과 Django admin 접근이 staff/superuser 권한에 의존한다.

Common Timestamp Columns

TimestampedModel은 공통 abstract model이다. 시간대 결정이 아니라 생성/수정 시각을 반복 없이 남기기 위한 구조다.

apps.common.models
Column Purpose MVP justification
created_at 행이 처음 생성된 시각을 기록한다. 계정, 소셜 연결, 혜택 claim의 운영 이력 확인에 필요하다.
updated_at 행이 마지막으로 변경된 시각을 기록한다. 탈퇴/익명화, 소셜 연결 상태 변경 같은 운영 변경 이력을 추적한다.

User

서비스 대표 계정이다. 이메일 로그인, Django 권한, 탈퇴 익명화, 이메일/전화 인증 상태를 담는다.

accounts.User
Column Purpose MVP justification
id 내부 primary key. 모든 관계형 모델의 기본 식별자다.
email 로그인 식별자이자 서비스 대표 이메일. Phase 0B 결정: custom User는 email로 로그인한다.
password Django password hash. 원문 비밀번호는 저장하지 않는다. 이메일/비밀번호 가입과 관리자 로그인 baseline에 필요하다.
username 로그인 ID가 아닌 화면 표시용 unique handle. Phase 0B username 정책: 자동 생성하고 unique로 둔다.
username_changed_at 사용자가 username을 직접 변경한 마지막 시각. 30일 1회 변경 제한을 검증하기 위한 최소 상태다.
name 사용자가 나중에 설정할 수 있는 실명 또는 표시 이름. 가입 시 필수는 아니지만 주문/마이페이지 계정 정보에 필요하다.
phone_e164 SMS 인증 후 저장되는 정규화 전화번호. 웰컴 혜택 중복 방지를 phone 기준으로 처리하기 위한 기반이다.
phone_verified_at 전화번호 인증 완료 시각. 인증된 phone만 혜택 지급 기준으로 삼기 위해 필요하다.
email_verified_at 대표 이메일 인증 완료 시각. 소셜 자동 연결은 email 인증 여부가 account pre-hijacking 방어 기준이다.
is_active 로그인 가능한 활성 계정 여부. 탈퇴 계정과 정지 계정을 로그인 lookup에서 제외한다.
is_staff Django admin과 관리자 REST 접근 가능 여부. Phase 0B 관리자 REST baseline은 staff 권한을 사용한다.
is_superuser Django permission 전체 권한 플래그. Django 권한 체계를 그대로 사용하기 위한 필수 상속 필드다.
deleted_at soft delete와 익명화 처리 시각. 탈퇴 후 같은 이메일/전화번호 재가입을 허용하면서 감사 흔적을 남긴다.
last_login 마지막 로그인 시각. Django auth 기본 운영 정보로 계정 보안 확인에 사용한다.
date_joined 가입 시각. 가입/혜택/운영 문의 기준 시각으로 필요하다.
created_at, updated_at 생성/수정 시각. 운영 감사와 데이터 변경 추적을 위한 공통 필드다.
groups, user_permissions Django group/permission 관계. seller 권한은 만들지 않고 Django 권한 체계로 관리자 권한을 시작한다.

SocialAccount

Kakao/Naver 계정과 내부 User를 연결하는 모델이다. provider identity를 1차 식별자로 보고, 탈퇴 시 비활성화/익명화한다.

accounts.SocialAccount
Column Purpose MVP justification
user_id 연결된 내부 User. 소셜 로그인 결과를 서비스 계정 하나로 귀속한다.
provider 소셜 provider. 현재 kakao, naver. Phase 0B 초기 소셜 범위가 Kakao/Naver다.
provider_user_id provider가 제공한 사용자 식별자. 소셜 계정의 가장 안정적인 lookup key다.
provider_email 로그인 시점 provider email snapshot. 자동 연결 판단과 운영 디버깅 근거이며 대표 이메일은 아니다.
provider_email_verified provider email 인증 여부 snapshot. 기존 email 계정과 자동 연결할 때 보안 조건으로 사용한다.
is_active 현재 로그인 lookup에 사용할 수 있는 연결인지 표시. 탈퇴/해제된 소셜 연결을 재사용하지 않기 위해 필요하다.
linked_at 소셜 연결 시각. 계정 연결 이력과 사용자 문의 대응에 필요하다.
deleted_at 소셜 연결 비활성화 시각. 탈퇴 시 hard delete하지 않는 정책을 표현한다.
anonymized_at provider identity/email 익명화 시각. unique slot 해제와 개인정보 최소 보관을 동시에 만족한다.
created_at, updated_at 생성/수정 시각. 소셜 연결 상태 변경 이력을 추적한다.

EmailChangeRequest

대표 이메일 변경을 새 이메일 인증 완료 전까지 보류하는 요청 모델이다. 원문 token은 저장하지 않고 hash만 저장한다.

accounts.EmailChangeRequest
Column Purpose MVP justification
user_id 이메일 변경을 요청한 User. 대표 이메일은 계정에 귀속되는 값이다.
new_email 변경하려는 새 대표 이메일. 인증 완료 전까지 기존 User.email을 유지하기 위해 별도 보관한다.
token_hash 이메일 인증 링크 token의 hash. 원문 token 저장 없이 one-time 확인을 처리한다.
expires_at 요청 만료 시각. Phase 0B 결정: 이메일 변경 요청은 24시간 뒤 만료한다.
confirmed_at 새 이메일 인증 완료 시각. 재사용 방지와 확정 여부 판단에 필요하다.
created_at 요청 생성 시각. 같은 user 기준 10분 1회 재요청 제한을 검증한다.

UserToken

이메일 인증, 비밀번호 설정, 비밀번호 재설정처럼 user-bound one-time token이 필요한 작업을 공통으로 표현한다.

accounts.UserToken
Column Purpose MVP justification
user_id token이 귀속된 User. 토큰 작업은 특정 계정에 대해 수행된다.
purpose email_verify, password_set, password_reset 구분. 같은 token 구조를 여러 인증 작업에 재사용한다.
token_hash one-time token hash. 원문 token을 DB에 저장하지 않기 위한 보안 기준이다.
expires_at token 만료 시각. email verify 24시간, password set/reset 1시간 정책을 강제한다.
consumed_at token 사용 완료 시각. one-time token 재사용을 막는다.
created_at token 생성 시각. 운영 문의와 token 발급 이력 확인에 필요하다.

BenefitClaim

웰컴 혜택 중복 지급을 막는 ledger다. 원문 개인정보는 저장하지 않고 서버 secret pepper 기반 HMAC hash 값만 저장한다.

accounts.BenefitClaim
Column Purpose MVP justification
code 혜택 종류. 현재 welcome_signup. MVP 중복 방지 대상은 웰컴 혜택이다.
user_id 혜택을 받은 User. nullable. 탈퇴 후에도 ledger는 남기되 User 참조는 끊길 수 있어야 한다.
phone_hash 전화번호 HMAC hash. 웰컴 혜택은 SMS 인증 phone 기준으로 1회만 지급한다.
email_hash 이메일 HMAC hash. 현재 보조 감사 정보. 원문 저장 없이 부정 이용 분석 근거를 확장할 수 있다.
social_identity_hash 소셜 identity HMAC hash. 현재 보조 감사 정보. 가입 경로별 중복 시도 분석에 원문 없이 사용할 수 있다.
claimed_at 혜택 claim 시각. 고객 문의와 부정 이용 조사 시점 기준이다.
claim_source 혜택 지급 트리거 출처. MVP 정책상 SMS 인증 완료 후 지급됨을 운영상 확인한다.
metadata 비식별 부가 정보. 부정 이용 대응에 필요한 최소 운영 정보를 구조적으로 남긴다.

Constraints And Indexes

모델 목적을 실제 DB 제약과 연결해서 확인한다.

migration 0001

User phone partial unique

phone_e164는 인증 완료 및 미탈퇴 User 기준으로 unique다. 탈퇴 시 phone을 제거하므로 같은 번호 재가입은 가능하다.

MVP 필요: 웰컴 혜택 중복 지급 방지.

Social identity unique

(provider, provider_user_id)와 (user, provider)가 unique다. 한 provider 계정은 하나의 내부 User에만 연결된다.

MVP 필요: Kakao/Naver 로그인 계정 연결 안정성.

Benefit welcome unique

welcome_signup은 phone_hash가 필수이며 (code, phone_hash)가 unique다.

MVP 필요: phone 기준 1회 지급 정책.

Token lookup indexes

token_hash, user/purpose/consumed/expires 조합 index를 둔다. token 검증과 미사용 token 조회를 빠르게 하기 위한 운영상 최소 index다.

MVP 필요: 이메일 인증과 비밀번호 token flow.

Deferred On Purpose
