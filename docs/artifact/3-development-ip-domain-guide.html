DNS가 IP를 알려주면 웹사이트도 바로 열리나요?

DNS는 목적지 정보만 반환합니다. 이후 공인 IP로 도달하는 네트워크 경로, 443 인바운드 규칙, TLS 인증서와 HTTPS 서버, 앱이 각각 준비돼야 합니다. TRACEBACK의 현재 상태는 바로 아래에서 단계별로 표시합니다.

서버의 IP가 바뀌면 무엇을 수정해야 하나요?

도메인의 A 레코드가 예전 IP를 가리키면 새 IP로 바꿔야 합니다. TTL 동안 오래된 답이 캐시에 남을 수 있습니다. 고정 공인 IP를 쓰면 서버 재시작 때문에 A 레코드를 자주 바꿀 필요가 줄어듭니다. 주소가 바뀌어도 HTTPS 인증서는 IP가 아닌 도메인 이름을 대상으로 검증하는 것이 일반적입니다.

위의 일반 경로에 TRACEBACK의 실제 도메인·DNS 레코드·EIP를 넣습니다. 이름 조회 이후의 HTTPS 구간은 아직 별도 작업입니다.

Route 53은 A 레코드를 DNS 응답으로 사용합니다. Vercel은 배포할 때 client의 vercel.ts가 읽는 DJANGO_ORIGIN으로 API rewrite를 만듭니다. 저장소에 AWS DNS 설정용 IaC 파일은 없으므로 위 첫 두 줄은 현재 콘솔값을 읽기 쉬운 형태로 옮긴 것입니다. Vercel은 2026-10-04 재배포로 rewrite가 적용됐지만 API HTTPS 연결이 거부되어 인증 요청은 아직 502입니다.

실제 값을 보았으니 각 숫자와 이름의 역할을 분리합니다. 이 구분이 있어야 IP를 바꿀 때 DNS에서 무엇을 수정할지 알 수 있습니다.

DNS는 도메인 이름에 대응하는 IP 같은 정보를 알려주는 체계입니다. Route 53은 그 DNS 정보를 관리하는 AWS 서비스입니다.

Elastic IP는 AWS 계정에 할당해 두는 공인 IPv4 주소입니다. 이번에는 개발 EC2에 연결했으므로 EC2를 중지했다 켜도 같은 IP를 유지합니다.

도메인 등록과 DNS 관리: 등록은 도메인 이름을 일정 기간 사용할 권리를 확보하는 일이고, DNS 관리는 그 이름이 어느 IP나 서비스로 연결되는지 정하는 일입니다. 이번에는 Route 53에서 도메인을 등록했고, Route 53 hosted zone에 DNS 레코드도 만들었습니다.
도메인을 산 회사와 DNS를 관리하는 회사가 같아야 하나요?

같을 필요는 없습니다. 등록업체는 이름의 사용 권리를 관리하고, 권한 DNS 제공업체는 레코드의 답을 관리합니다. 등록업체에 어느 네임서버를 사용할지 지정해 둘을 연결합니다. TRACEBACK은 등록과 DNS 관리를 모두 Route 53에서 하므로 운영 화면이 한곳에 있습니다. 등록·네임서버·조회 전체 그림 보기

이름과 IP의 관계를 알았다면, EC2가 재시작할 때 IP가 유지되는지 선택할 수 있습니다.

도메인과 권한 DNS 준비

Route 53 → Registered domains에서 도메인을 등록했다면 자동 생성된 같은 이름의 public hosted zone을 사용합니다. 등록 도메인의 네임서버가 그 zone의 NS와 일치하는지 확인하세요. 이미 다른 zone을 쓰거나 외부 등록업체에서 도메인을 샀다면 사용할 zone의 NS를 등록업체에 위임해야 합니다.

EC2에 EIP 연결

비용도 설정 경로마다 따로 발생: EIP는 EC2가 중지돼도 시간당 요금이 계속됩니다. RDS는 실행 중 instance-hour 요금이 발생하고, 중지해도 storage/backup 비용이 남을 수 있습니다. 따라서 “환경변수를 넣었다”는 것과 “서비스가 연결되어 실제 동작한다”는 것은 별도 확인 단계입니다.

문서 위치: 2번 배포 가이드 다음에 이 주소·EIP 선택을 읽고, 이어서 4번 DNS 원리를 봅니다. 전체 AWS 흐름은 System Guide에서 확인할 수 있습니다.
