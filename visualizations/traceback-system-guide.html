두 번 검증하고, 한 번 만든 이미지를 승격합니다

feature PR은 코드를 검증하고, development push가 이미지를 ECR에 올립니다. main은 새 이미지를 만들지 않고 development에서 배포에 성공한 digest를 사용합니다.

feature→ PR →development→ PR →main
동일 image digestdevelopment ECR image → production EC2 · 운영에서 재빌드 없음

두 환경이 공통으로 실행하는 EC2 단계

deploy-ec2.sh · docker-compose.yml + docker-compose_prod.yml
01 · RUNNERdigest 확인·SSM 전송sha256 URI 형식을 검사하고 대상 EC2에 명령을 보냅니다.
02 · EC2ECR login·pullEC2 instance role로 이미지를 받습니다.
03 · IMAGECompose 추출이미지에 들어 있는 개발 Compose와 운영 override를 복사합니다.
04 · DATABASE설정 검사·migrate운영 override는 로컬 DB·포트·볼륨을 제거하고 외부 DB URL을 씁니다.
05 · APPup --wait앱 컨테이너를 교체하고 allauth config HTTP healthcheck를 기다립니다.

현재 workflow·이미지 빌드·로컬 smoke는 검증됐지만 실제 AWS 배포는 아직 아닙니다. 이 healthcheck는 컨테이너 내부 확인이며 외부 reverse proxy/TLS와 자동 rollback은 별도입니다.
